# 闭包(closure)

如果**内部函数引用了外层函数作用域里的变量**，外层函数返回这个内部函数，这个内部函数就是**闭包 (closure)**。

## 实现闭包的三个条件

- **嵌套函数**: 函数内部定义函数
- **内层函数引用外层函数的变量**(自由变量)
- **外层函数返回内层函数**(或以其他方式让内层函数在外部被使用)

```python
def outer(x):
    def inner(y):
        return x + y        # inner 引用了外层的 x
    return inner            # 返回内层函数

add5 = outer(5)             # outer 执行完毕
print(add5(10))             # 15，x=5 依然被保留
print(add5(20))             # 25
```

`outer(5)` 返回后，它的局部变量 `x` 本应被销毁，但因为 `inner` 还引用着它，Python 把 `x` 保存在 `inner` 的闭包里，所以 `add5(10)` 仍然能用到 `x=5`。

## 闭包的本质：`__closure__`

每个函数对象都有 `__closure__` 属性，存放它捕获的自由变量：

```python
def outer(x):
    def inner(y):
        return x + y
    return inner

add5 = outer(5)

print(add5.__closure__)          # (<cell at 0x...: int object at 0x...>,)
print(add5.__closure__[0].cell_contents)   # 5
print(add5.__code__.co_freevars)           # ('x',)
```

结构关系：

```text
add5 (function)
 ├── __code__.co_freevars = ('x',)        自由变量名
 └── __closure__ = (cell(x),)            cell 对象，装着实际值
```

**cell 是 “变量盒子”** ：闭包捕获的不是值的副本，而是 **变量本身所在的cell** 。所以后续修改这个变量，闭包看到的是新值。

```python
def counter():
    n = 0
    def inc():
        return n
    n = 100          # 修改 cell 里的值
    return inc

c = counter()
print(c())           # 100，不是 0
```

## `nonlocal`：在闭包里修改外层变量

内层函数 **读取** 外层变量不需要声明；但 **赋值** 时会出问题：

```python
def counter():
    n = 0
    def inc():
        n += 1       # UnboundLocalError
        return n
    return inc
```

原因：`n += 1` 让Python认为 `n` 是 `inc` 的局部变量，单赋值前有没定义，报错。
用 `nonlocal` 声明 “我要改的是外层那个 `n`”：

```python
def counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

c = counter()
print(c(), c(), c())     # 1 2 3
```

**作用域关键词对比**：

| 关键词 | 作用 |
|---|---|
| 无 | 读外层变量可以，写就变成局部变量 |
| `global` | 声明变量属于模块全局作用域 |
| `nonlocal` | 声明变量属于最近的 **外层函数** 作用域(不能是全局) |

```python
x = 0
def f():
    global x
    x = 1        # 改全局

def g():
    y = 0
    def h():
        nonlocal y
        y = 1    # 改 g 的局部变量
    h()
    return y
```

## 闭包的经典应用

### 1、工厂函数：生成带状态的函数

```python
def make_multiplier(k):
    def mul(x):
        return x * k
    return mul

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(10), triple(10))    # 20 30
```

每个返回的函数都有 **独立的状态(`k = 2` 和 `k = 3` 互不干扰)**

### 2、计数器/累加器

```python
def make_counter(start=0):
    count = start
    def counter():
        nonlocal count
        count += 1
        return count
    return counter

c1 = make_counter()
c2 = make_counter(100)
print(c1(), c1(), c2())    # 1 2 101
```

### 3、装饰器(闭包的典型应用)

```python
import functools

def log(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}")
        return func(*args, **kwargs)
    return wrapper       # wrapper 闭包捕获了 func

@log
def add(a, b):
    return a + b

print(add(1, 2))
# 调用 add
# 3
```

装饰器本质就是 “接收函数、返回闭包” 的高阶函数。`wrapper` 捕获了 `func` ，每次调用 `add` 实际执行 `wrapper` 。

#### 函数装饰器详解

装饰器是接收一个函数、返回一个新函数(通常是闭包)的可调用对象，用来在不修改原函数代码的前提下增强其行为。

##### 一、从最朴素的写法开始

###### 不用装饰器时
想给函数加日志，最直接的办法是包一层：

```python
def add(a, b):
    return a + b

def logged_add(a, b):
    print(f"调用 add({a}, {b})")
    res = add(a, b)
    print(f"add 返回结果：{res}")
    return res


print(logged_add(1, 2))
# 调用 add(1, 2)
# add 返回结果：3
# 3
```
问题：每加一个函数就要写一个 wrapper，重复且容易出错

> wrapper 就是一层薄薄的 “外壳代码”，包住原有函数 / 类 / 接口，不改里面原逻辑，只在前后加额外逻辑
> wrap:包裹，wrapper：用来包裹它的东西

###### 用函数工厂生成 wrapper

```python
def log_wrapper(func):
    def inner(*args, **kwargs):
        print(f"调用 {func.__name__}{args}")
        res = func(*args, **kwargs)
        print(f"{func.__name__} 结果: {res}")
        return res
    return inner  # inner闭包捕获了 func

add = log_wrapper(add) # 手动 “装饰”
print(add(1, 2))
# 调用 add((1, 2), {})
# 3
```

`log_wrapper` 就是装饰器：**接收函数** `func` ，**返回闭包** `inner`。`inner`在调用前后插入逻辑，中间调用原函数

###### 语法糖 `@`

```python
@log_wrapper
def add(a, b):
    return a + b
```

完全等价于：

```python
def add(a, b):
    return a + b
add = log(add)
```

`@log` 放在 `def` 上方，Python 会自动执行 `add = log(add)`

##### 二、装饰器的执行时机

关键点：**装饰发生在函数定义是，而不是调用时**

```python
def log(func):
    print(f"装饰 {func.__name__}")     # 定义时执行
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}")  # 调用时执行
        return func(*args, **kwargs)
    return wrapper

@log
def add(a, b):
    return a + b

print("--- 定义完成 ---")
add(1, 2)
```

输出：

```ini
装饰 add
--- 定义完成 ---
调用 add
```

执行顺序：

1. 解释器读到 `@log` ,调用 `log(add)` ，此时 `add` 还是原函数。
2. `log` 返回 `wrapper`，`add`这个名字被重新绑定为 `wrapper`
3. 之后调用 `add(1, 2)`,实际执行 `wrapper(1, 2)`

**所以 `@` 不是“运行时才套壳”，而是“定义时就把名字换掉了”。**

##### 三、基础模板

```python
import functools

def decorator(func):
    @functools.wraps(func)          # 保留原函数元信息
    def wrapper(*args, **kwargs):
        # 调用前逻辑
        result = func(*args, **kwargs)
        # 调用后逻辑
        return result
    return wrapper
```

三个要点：
1. `*args, **kwargs`：让 `wrapper` 能接收任意参数，适配任意被装饰函数。
2. `return func(...)`：必须把原函数返回值返回，否则调用方拿到 `None` 。
3. `@functools.wraps(func)`：保留 `__name__`、`__doc__`、`__module__` 等元信息(下面细讲)。

##### 四、`functools.wraps 为什么重要`

不加 `wraps` 时：

```python
def log(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@log
def add(a, b):
    """两数相加"""
    return a + b

print(add.__name__)    # wrapper，不是 add
print(add.__doc__)     # None，文档丢了
```

这会影响调试、日志、`help()`、以及依赖函数签名的框架(如 Flask路由、FastAPI参数解析)

加 `wraps`后：

```python
import functools

def log(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

print(add.__name__)    # add
print(add.__doc__)     # 两数相加
```

`wraps` 还会设置 `__wrapped__` 属性指向原函数，可以用 `inspect.unwrap()` 拿到原函数

**结论：写装饰器几乎总是要加 `@functools.wraps(func)`**

##### 五、带参数的装饰器

###### 1、需求

想给装饰器传参数，比如指定日志前缀：

```python
@log("DEBUG")
def add(a, b): ...
```

###### 2、原理：三层嵌套

带参数的装饰器本质是“**返回装饰器的函数**”：

```python
import functools

def log(prefix):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(f"[{prefix}] 调用 {func.__name__}")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@log("DEBUG")
def add(a, b):
    return a + b

add(1, 2)
# [DEBUG] 调用 add
```

展开来看：

```python
add = log("DEBUG")(add)
# 1. log("DEBUG") 返回 decorator
# 2. decorator(add) 返回 wrapper
# 3. add = wrapper
```

三层结构记忆法：

| 层 | 作用 | 参数 |
|---|---|---|
| 最外层 | 接收装饰器参数 | `prefix` |
| 中间层 | 接收被装饰函数 | `func` |
| 最内层 | 真正的 wrapper | `*args, **kwargs` |

###### 3、常见变体：可选参数

希望 `@log` 和 `@log("DEBUG")` 都能用，可以这样写：

```python
import functools

def log(arg=None):
    # 不带参数：@log 直接传函数进来
    if callable(arg):
        func = arg
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(f"调用 {func.__name__}")
            return func(*args, **kwargs)
        return wrapper

    # 带参数：arg 是前缀，返回真正的装饰器
    prefix = arg
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(f"[{prefix}] 调用 {func.__name__}")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@log
def f(): ...

@log("DEBUG")
def g(): ...
```

这种写法在 Flask、pytest等库里很常见，但可读性较差，非必要不推荐

##### 六、类装饰器

###### 1、用类实现装饰器

只要类实现了 `__call__`，实例就可以当装饰器用：

```python
import functools

class Log:
    def __init__(self, func):
        functools.update_wrapper(self, func)   # 保留元信息
        self.func = func

    def __call__(self, *args, **kwargs):
        print(f"调用 {self.func.__name__}")
        return self.func(*args, **kwargs)

@Log
def add(a, b):
    return a + b

add(1, 2)
# 调用 add
```

适合装饰器需要 **保存状态的场景**，比如统计调用次数：

```python
class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func = func
        self.count = 0

    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"{self.func.__name__} 已被调用 {self.count} 次")
        return self.func(*args, **kwargs)

@CountCalls
def say():
    print("hi")

say(); say()
# say 已被调用 1 次
# hi
# say 已被调用 2 次
# hi
```

> 注意：类装饰器保留元信息用 `functools.update_wrapper(self, func)`，不是 `wraps`

###### 2、装饰类(把类当被装饰对象)

装饰器不知能装饰函数，也能装饰类：

```python
def add_repr(cls):
    def __repr__(self):
        return f"{cls.__name__}({self.__dict__})"
    cls.__repr__ = __repr__
    return cls

@add_repr
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

print(Point(1, 2))     # Point({'x': 1, 'y': 2})
```

`@dataclass` 就是最著名的类装饰器

##### 七、多个装饰器叠加

```python
@a
@b
@c
def f(): ...
```

等价于：

```python
f = a(b(c(f)))
```

**离函数最近的先执行，包裹顺序从内到外。**

```python
def bold(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def italic(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

@bold
@italic
def text():
    return "hello"

print(text())    # <b><i>hello</i></b>
```

展开：`text = bold(italic(text))`。调用时先进入 `bold.wrapper`，在进入`italic.wrapper`，最后到原函数。

**顺序很重要**：交换 `@bold` 和 `@italic` ，输出变成 `<i><b>hello</b></i>`

##### 八、常见应用场景

###### 1、日志

```python
def log(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}{args}")
        return func(*args, **kwargs)
    return wrapper
```

###### 2、计时

```python
import time, functools

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.perf_counter() - start:.4f}s")
        return result
    return wrapper
```

###### 3、缓存

```python
import functools

@functools.lru_cache(maxsize=128)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```

标准库 `lru_cache` 就是装饰器，用字典缓存参数到结果的映射。

###### 4、权限校验/登录检查

```python
def require_login(func):
    @functools.wraps(func)
    def wrapper(user, *args, **kwargs):
        if not user.is_authenticated:
            raise PermissionError("请先登录")
        return func(user, *args, **kwargs)
    return wrapper

class User:
    is_authenticated = False

@require_login
def view_profile(user):
    return "个人主页"

# view_profile(User())   # PermissionError
```

Web框架里的 `@app.route`、`@login_required` 都是这个套路。

###### 5、重试

```python
import time, functools

def retry(times=3, delay=1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for i in range(times):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_exc = e
                    print(f"第 {i+1} 次失败：{e}")
                    time.sleep(delay)
            raise last_exc
        return wrapper
    return decorator

@retry(times=3, delay=0.5)
def fetch():
    ...
```

###### 6、参数校验/类型检查

```python
def validate_positive(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        if any(isinstance(a, (int, float)) and a < 0 for a in args):
            raise ValueError("参数不能为负")
        return func(*args, **kwargs)
    return wrapper
```

###### 7、注册函数(插件机制)

```python
registry = {}

def register(name):
    def decorator(func):
        registry[name] = func
        return func
    return decorator

@register("add")
def add(a, b): return a + b

@register("sub")
def sub(a, b): return a - b

print(registry)     # {'add': <function add>, 'sub': <function sub>}
```

Flask的路由、pytest的fixture 都基于这种模式。

##### 九、标准库现成的装饰器

| 装饰器 | 作用 |
|---|---|
| `@functools.wraps` | 保留被装饰函数元信息 |
| `@functools.lru_cache` | 缓存函数结果|
| `@functools.cache` | 3.9+，无大小限制的缓存 |
| `@functools.cache_property` | 把方法结果缓存为属性 |
| `@functools.singledispatch` | 按第一个参数类型分派 |
| `@functools.total_ordering` | 自动补齐比较方法 |
| `@staricmethod`/`@classmethod`/`@property` | 类相关 |
| `@contextlib.contextmanager` | 用生成器写上下文管理器 |
| `@dataclasses.dataclass` | 自动生成 `__init__` 等 |
| `@typing.final` | 标记不可重写/继承 |
| `@abc.abstractmethod` | 声明抽象方法 |
| `@unittest.skip`/`@pytest.mark.parametrize` | 测试框架 |

很多“框架语法”本质都是装饰器


##### 十、常见坑

###### 1、忘了 `return func(...)`

```python
def bad(func):
    def wrapper(*args, **kwargs):
        func(*args, **kwargs)      # 没 return
    return wrapper

@bad
def add(a, b):
    return a + b

print(add(1, 2))    # None
```

###### 2、忘了 `@functools.wraps`

导致 `__name__`、`__doc__`、签名丢失，影响调试和依赖签名的框架。

###### 3、带参数装饰器少一层

```python
def log(prefix):          # 带参数
    def decorator(func):
        def wrapper(*args, **kwargs):
            ...
        return wrapper
    return decorator
```

写成两层会报 `TypeError: 'function' object is not callable` 或装饰器收到函数而非参数。

###### 4、装饰器定义时执行副作用

```python
def log(func):
    print("装饰时执行")     # 每次 import 都会打印
    ...
```

装饰发生在定义/导入阶段，副作用会提前触发。需要延迟到调用时再做。

###### 5、多个装饰器顺序搞反

`@a @b` 是 `a(b(f))`，`b`先包裹。涉及状态、异常处理时顺序会改变行为。

###### 6、装饰器破坏了函数签名

`wrapper(*args, **kwargs)` 虽然能接任意参数，但 `inspect.signature` 会看到 `(*args, **kwargs)` 。`functools.wraps` 通过 `__wrapped__` 让 `inspect.signature` 能追溯到原函数，但一些框架仍可能受影响。必要时用 `inspect.signature` 手动设置。

###### 7、类方法/静态方法的装饰顺序

```python
class A:
    @log
    @staticmethod
    def f(): ...      # 先 staticmethod 再 log，通常可行

    @staticmethod
    @log
    def g(): ...      # 先 log 再 staticmethod，也可行，但要注意 log 收到的是普通函数

    @log
    @classmethod
    def h(cls): ...   # log 收到的是 classmethod 对象，不是普通函数，容易出错
```

装饰类方法时，通常 **把 `@log` 放在 `@classmethod`/`@staticmethod` 下面** 更安全，或者单独处理 `classmethod` 对象。

###### 8、循环里创建装饰器闭包变量延迟绑定

和闭包坑一样：

```python
decorators = []
for prefix in ["A", "B"]:
    def make(prefix=prefix):    # 默认参数固定
        ...
```

##### 十一、`functools.wraps` 到底做了什么

简化版实现：

```python
def wraps(wrapped):
    def decorator(wrapper):
        wrapper.__name__ = wrapped.__name__
        wrapper.__doc__ = wrapped.__doc__
        wrapper.__module__ = wrapped.__module__
        wrapper.__qualname__ = wrapped.__qualname__
        wrapper.__annotations__ = wrapped.__annotations__
        wrapper.__dict__.update(wrapped.__dict__)
        wrapper.__wrapped__ = wrapped
        return wrapper
    return decorator
```

所以它本质是 **把原函数的元信息复制到 wrapper 上**，并设置 `__wrapper__` 指针。
`inspect.unwrap(f)` 会顺着 `__wrapped__` 找到原函数。

##### 十二、最佳实践

1. **总是加** `@functools.wraps(func)`(类装饰器用 `functools.update_wrapper(self, func)`)
2. **wrapper 必须** `return func(...)`，除非你故意要改返回值
3. **用** `*args, **kwargs` **适配任意签名**
4. **装饰器只做横切关注点**：日志、计时、缓存、权限、重试。不要塞业务逻辑
5. **带参数装饰器保持三层结构**，命名清晰：`decorator`/`wrapper`
6. **多个装饰器注意顺序**，从内到外包裹，从外到内执行
7. **副作用尽量延迟到调用时**，避免 import 阶段做重活
8. **能用标准库就用标准库**：`lru_cache`、`contextmanager`、`dataclass` 别手写
9. **调试时可用** `inspect.unwrap(f)` 那会原函数。
10. **装饰器叠加过多会降低可读性**，必要时合并成一个。

##### 十三、一张图理清结构

```python
@decorator
def f(...): ...

        等价于

f = decorator(f)
```

带参数：

```python
@decorator(arg)
def f(...): ...

        等价于

f = decorator(arg)(f)
```

三层结构：

```text
decorator(arg)                    ← 最外层：接收装饰器参数
    └── decorator(func)           ← 中间层：接收被装饰函数
            └── wrapper(...)      ← 最内层：真正执行，调用 func
```

#### 一句话总结：

**装饰器 = 接收函数、返回闭包的可调用对象，`@` 是 `f = decorator(f)` 的语法糖；它在定义时执行、调用时生效。核心模板是 `wraps + wrapper(*args, **kwargs) + return func(...)`；带参数就多套一层，需要状态就用类实现 `__call__`。它适合日志、计时、缓存、权限、重试等横切逻辑，但不要用它承载业务本身。**

### 4、惰性求值/缓存

```python
def lazy_sum(nums):
    def compute():
        return sum(nums)
    return compute       # 不立刻计算

s = lazy_sum([1, 2, 3, 4])
print(s())               # 10，真正用到时才算
```

### 5、实现简易 “私有状态”

```python
def make_account(balance):
    def deposit(amount):
        nonlocal balance
        if amount <= 0:
            raise ValueError("金额必须为正")
        balance += amount
        return balance

    def withdraw(amount):
        nonlocal balance
        if amount > balance:
            raise ValueError("余额不足")
        balance -= amount
        return balance

    def get_balance():
        return balance

    return {"deposit": deposit, "withdraw": withdraw, "balance": get_balance}

acc = make_account(100)
acc["deposit"](50)
acc["withdraw"](30)
print(acc["balance"]())   # 120
# 外部无法直接访问 balance 变量，只能通过返回的函数操作
```

这和面向对象的封装效果类似，但没有类。

## 闭包的坑

### 1、循环变量延迟绑定(最经典)

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)

print([f() for f in funcs])    # [2, 2, 2]，不是 [0, 1, 2]
```

原因：闭包捕获的是 **变量 `i` 的cell**，循环结束时，`i = 2` ，三个lambda 共享同一个cell

#### 修复方式一：默认参数 **立即绑定**

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])    # [0, 1, 2]
```

默认参数在 **函数定义** 时求值，此时 `i` 的值被固定下来。

#### 修复方式二：再套一层函数(工厂)

```python
def make_func(i):
    return lambda: i

funcs = [make_func(i) for i in range(3)]
print([f() for f in funcs])    # [0, 1, 2]
```

每个 `make_func(i)` 调用创建了 **独立的cell**

### 2、闭包不能直接修改不可变外层变量

需要 `nonlocal` ，前面讲过

### 3、闭包对象有引用，可能导致内存不释放

闭包持有的 cell 会组织变量被 GC 。如果闭包捕获了很大对象且长期存活，可能造成内存占用。需要时显式解除引用。

### 4、调试不易

闭包里的状态不在 `obj.__dict__` 里，查看状态需要 `__closure__` 或调试工具，可读性比类属性差。

### 5、`nonlocal` 不能跨多层到全局

```python
x = 0
def outer():
    def inner():
        nonlocal x      # SyntaxError: no binding for nonlocal 'x'
```

`nonlocal` 只能找到外层 **函数** 作用域的变量，找不到就报错；该全局要用 `global` 。

## 闭包 vs 面向对象

这是很自然的对比，因为闭包也能 “保持状态”：

| 维度 | 闭包 | 类 |
|---|---|---|
| 状态存放 | cell(变量盒子) | 实例 `__dict__` |
| 公开操作 | 返回的函数 | 方法 |
| 封装性 | 强，外部拿不到变量 | 靠命名约定/`property` |
| 多方法 | 需返回多个函数 (dict组织) | 天然支持 |
| 可读性 | 简单状态时简洁 | 状态多、方法多时更清晰 |
| 继承/多态 | 不支持 | 支持 |
| 调试 | 较难 | 较好 |
| 性能 | 轻量，创建开销小 | 有类和实例开销 |
| 使用场景 | 单一状态、回调、装饰器 | 复杂对象、多行为、需要类型体系 |

大致原则：

- **状态简单、行为单一、一次性使用** -> 闭包
- **状态多、行为多、需要复用和扩展、需要类型关系** -> 类

```python
# 闭包版计数器
def counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

# 类版计数器
class Counter:
    def __init__(self):
        self.n = 0
    def inc(self):
        self.n += 1
        return self.n
```

功能相同，闭包版更短；类版更易扩展(比如加 `reset`、`__repr__`、继承)

## 闭包与 `functools.partial` 的区别

`functools.partial` 也能“固定部分参数”：

```python
from functools import partial

def add(x, y):
    return x + y

add5 = partial(add, 5)
print(add5(10))    # 15
```

区别：
- `partial` 是 **把已有参数绑定到一个现有函数**，不创建新作用域
- 闭包是 **新建内层函数**，可以捕获任意表达式的结果，还能在内部做逻辑。

```python
# partial 做不到的：带逻辑
def make_discount(rate):
    def apply(price):
        if price < 0:
            raise ValueError
        return price * (1 - rate)
    return apply
```

## 闭包与 `lambda` 的关系

`lambda` 只是 **匿名函数**，本身不是闭包。但当 `lambda` 引用了外层变量并被返回/传递时，它就形成了闭包：

```python
def make_adder(n):
    return lambda x: x + n     # lambda 闭包捕获 n

add10 = make_adder(10)
print(add10(5))                # 15
```

理解要点：
- `lambda` 是语法糖，等价于一个小函数
- **闭包是运行时的行为**，不是某种函数写法
- 普通 `def` 和 `lambda` 都能形成闭包

## 底层视角：`co_freevars` 与 `co_cellvars`

```python
def outer(x):
    y = 10
    def inner():
        return x + y
    return inner

print(outer.__code__.co_cellvars)    # ('x', 'y')  外层被内层引用的变量
print(outer(1).__code__.co_freevars) # ('x', 'y')  内层自由变量
```

- `co_cellvars`：当前函数里 **被内层函数引用** 的局部变量，存成cell。
- `co_freevars`：当前函数 **引用了外层** 的变量
- 运行时通过 `__closure__` 里的cell对象共享值

这就是 Python 闭包的实现机制：**编译器识别自由变量，运行时用 cell 包装，函数对象持有 cell 元组**

## 最佳实践

- **循环中创建闭包时，用默认参数或工厂函数固定变量**，避免延迟绑定坑
- **修改外层变量显式用** `nonlocal` ，不要依赖隐式行为。
- **状态简单用闭包，状态复杂用类**，不要硬用闭包模拟复杂对象
- **装饰器里用** `functools.wraps` 保留原函数元信息
- **注意闭包持有的对象生命周期**，大对象长期被闭包引用会延迟释放
- **闭包不要过度嵌套**，两层足够；三层以上可读性急剧下降。
- **优先用** `functools.partial` **做纯参数绑定**，闭包留给需要逻辑的场景。
