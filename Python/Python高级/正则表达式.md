# 第一章 本质：正则到底是什么

## 1.1、定义

正则表达式(Regular Expression) 是一个**描述字符串集合的形式化记号**。

```python
r"\d{3}" # 这个模式描述的式 {001, 002, ..., 999} 这 1000 个字符串的集合
```

“匹配” = 判断某个字符串 (或它的字串) **是否属于这个集合**

## 1.2、声明式 vs 过程式

|  | 过程式 | 声明式(正则) |
|---|---|---|
| 写法 | 循环 + 判断 + 索引 | 一条模式 |
| 关注点 | **怎么找** | **长什么样** |
| 例子 | `if len(s) == 10 and s[4] == '-': ...` | `r"\d{4}-\d{2}-\d{2}"` |
| 可维护性 | 逻辑清晰，但冗长 | 短，但可读性随复杂度崩坏 |

```python
# 判断是否为 4 位数字-2 位数字
s = "2026-10"
# 过程式
ok = len(s) == 7 and s[4] == "-" and s[:4].isdigit() and s[5:].isdigit()
# 声明式
ok = bool(re.fullmatch(r"\d{4}-\d{2}", s))
```

## 1.3、能力边界：正则语言与有限自动机

这是形式语言理论 (乔姆斯基谱系) 的结论：**正则语言 = 能被有限自动机识别的语言 = 3 型文法**。有限自动机 **没有记忆** (只有有限个状态)，所以：

| 需求 | 能否 | 原因 |
|---|---|---|
| 匹配 3 个数字 + 2 个字母 | 能 | 状态数有限 |
| 匹配“长度 8-20 的密码” | 能 | 只需计数到20，可用 `{8, 20}` |
| 匹配 `a^n b^n` (n 个 a 后面跟 n 个 b) | 不能 | 需要无限计数 |
| 匹配任意深度的括号 `((()))` | 不能 | 需要栈 |
| 匹配成对的 HTML 标签 | 不能 | 需要栈 |

> **实践推论**：遇到“配对 / 嵌套 / 递归”结构，正则一定不够用。这不是写得好不好的问题，是 **理论边界**。

## 1.4、三种引擎

| 引擎 | 代表 | 匹配策略 | 复杂度 | 支持反向引用/断言 |
|---|---|---|---|---|
| **DFA**(自动机) | RE2、GO `regexp` 、Rust `regex` | 并行状态推进 | **O(n-m)** 线性 | 不支持 |
| **回溯 NFA** | Python `re`、Perl、PCRE、Java、JS | 深度优先试错 | **最坏O(2^n)** | 支持 |
| **POSIX NFA** | `grep -E`、`awk` | 回溯，但取 **最长** 匹配 | 最坏指数 | 有限 |

### 关键差异：`a|ab` 匹配 `"ab"`

| 引擎类型 | 结果 | 原因 |
|---|---|---|
| 回溯型 (Python / Perl) | `a` | 最左 **首次** 匹配，`a` 先成功就返回 |
| POSIX | `ab` | 最左 **最长** 匹配 |

```python
re.match(r"a|ab", "ab").group()   # 'a'
```

## 1.5、方言差异 (换语言必查)

| 特性 | **Python** `re` | **PCRE / Perl** | **POSIX** | **RE2 / GO** |
|---|---|---|---|---|
| 命名分组 | `(?P<n>x)` | `(?<n>x)` | 无 | `(?P<n>x)` |
| 非捕获组 | `(?:x)` | `(?:x)` | 无 | `(?:x)` |
| 环视 | 支持 | 支持 | 不支持 | 不支持 |
| 反向引用 | 支持 | 有支持 | BER 有  | 无 |
| 递归 | 不支持 | 支持 `(?R)` | 不支持 | 不支持 |
| 条件模式 | 支持 `(?(1)a\|b)` | 支持 | 不支持 | 不支持 |
| 原子组 / 占有量词 | 支持 3.11+ | 支持 | 不支持 | 不适用 |
| POSIX 字符类 `[[:alpha:]]` | 不支持 | 部分 | 支持 | 支持 |
| Unicode 属性 `\p{Han}` | 不支持 | 支持 | 不支持 | 支持 |

> Python 里 `\p{...}` 不支持，需要中文范围就用 `[\u4e00-\u9fa5]`，或装 `regex` 模块。

## 本章要点

1. 正则描述的是“字符串集合”，匹配 = 判断属于关系。
2. **不能计数、不能嵌套** -- 这是理论限制。
3. Python 是 **回溯引擎**，功能强但可能指数级。
4. 方言不通用，换语言要重测。

# 第二章 字符：匹配“一个字符”

## 2.1、元字符清单 (需要转义的)

```python
.  ^  $  *  +  ?  {  }  [  ]  (  )  |  \
```

其余字符都是字面量。要匹配元字符本身，加 `\`:

```python
re.findall(r"\.", "3.14")      # ['.']
re.findall(r"a\+b", "a+b")     # ['a+b']
re.escape("a.b*c")             # 'a\\.b\\*c'  ← 批量转义，拼动态正则必用
```

## 2.2、预定义字符类

| 写法 | 匹配 | 取反 |
|---|---|---|
| `\d` | 数字 (Unicode Nd, 含全角) | `\D` |
| `\w` | 字母 / 数字 / 下划线 / 汉字 | `\W` | 
| `\s` | 空白：空格 `\t \n \r \f \v` | `\S` |
| `.` | 任意字符 (**默认不含换行**) | --- |

> 记忆：**小写 = 是，大写 = 不是**；
> `\S` 是“非空白”，
> `\D` 是“非数字”

```python
re.findall(r"\d+", "订单 2026 号")     # ['2026']
re.findall(r"\w+", "user_name-42")    # ['user_name', '42']
re.findall(r"\S+", " a  b ")          # ['a', 'b']
```

`.` 的坑

```python
re.findall(r"a.b", "a\nb")                  # []        默认不匹配换行
re.findall(r"a.b", "a\nb", re.S)            # ['a\nb']   re.DOTALL
re.findall(r"a[\s\S]b", "a\nb")             # ['a\nb']   不用 flag 的写法
```

## 2.3、自定义字符类 `[...]`

| 写法 | 含义 |
|---|---|
| `[abc]` | a、b、c 之一 |
| `[a-z]` | 小写字母之一 |
| `[a-zA-Z0-9_]` | 字母数字下划线 |
| `[^abc]` | 除 a、b、c 外任意一个 (**含换行**) |
| `[.]` | 字面点好 (类内 `.` 无特殊含义) |
| `[\d\s]` | 数字或空白 (类内可嵌预定义类) |

```python
re.findall(r"[aeiou]", "hello world")      # ['e', 'o', 'o']
re.findall(r"[^0-9\s]", "a1 b2")           # ['a', 'b']
```

### 类内的四个特殊位置

| 符号 | 规则 |
|---|---|
| `^` | 只在 **开头** 表示取反；`[a^]` 里的是字面量 |
| `-` | 只在 **中间** 表示范围；`[-a]`、`[a-]` 里是字面量 |
| `]` | 要放 **第一个** 位置才是字面量：`[]a]` |
| `\` | 仍需转义 |

```python
re.findall(r"[a-]", "a-b")     # ['a', '-']  末尾的 - 是字面量
re.findall(r"[-a]", "-a")      # ['-', 'a']
```

## 2.4、Unicode 语义：默认“很宽”

Python 3 的 `str` 是Unicode，`\d` `\w` 默认按Unicode 规则：

| 模式 | 输入 | 默认 | `re.ASCII` |
|---|---|---|---|
| `\d` | `1` (全角) | 匹配 | 不匹配 |
| `\w` | `中` | 匹配 | 不匹配 |
| `\w` | `é` | 匹配 | 不匹配 |
| `\d` | `١٢٣` (阿拉伯数字) | 匹配 | 不匹配 |

```python
re.fullmatch(r"\d+", "１２３")             # 匹配！
re.fullmatch(r"\d+", "１２３", re.ASCII)   # None ✓
```

> **表单校验一律加** `re.ASCII`，否则“全角数字”和“其他语言的数字”会混进来。
> `bytes` 上的正则天然按字节处理，
> `\w` 只认 ASCII

## 2.5、速查：常用字符类等价写法

| 需求 | 推荐 | 不推荐 |
|---|---|---|
| 数字 | `\d` | `[0-9]` (非 ASCII 场景才用) |
| 字母 | `[a-zA-Z]` | `[[:alpha:]]` (Python 不支持！) |
| 中文 | `[\u4e00-\u9fa5]` | `\w` (太宽) |
| 非空白 | `\S` | `[^ \t\n\r\f\v]` |
| 任意 (含换行) | `[\s\S]` | `\.` + `re.S` (要记 flag) |

## 本章要点

1. 元字符仅 13 个，其余是字面量
2. 小写是“是”，大写是“不是”
3. `[...]` 里 `.` `*` 等失去特殊含义，只有 `^ - ] \` 需要注意位置
4. `\d \w` 默认Unicode，校验加 `re.ASCII` 
5. Python **不支持** POSIX `[[:alpha:]]`，实测会静默匹配失败

# 第三章 量词：匹配“多少”个

## 3.1、六种量词

| 写法 | 次数 | 等价 |
|---|---|---|
| `*` | 0 或多次 | `{0,}` |
| `+` | 1 或多次 | `{1,}` |
| `?` | 0 或 1 次 | `{0,1}` |
| `{n}` | 正好 n 次 | --- |
| `{n,m}` | n 到 m 次 | --- |
| `{n,}` | 至少 n 次 | --- |

```python
re.fullmatch(r"\d{4}-\d{2}-\d{2}", "2026-10-29")   # 匹配
re.fullmatch(r"colou?r", "color")                  # 匹配（u 可有可无）
```

## 3.2、量词作用于“前一个原子”

```python
r"ab*"    # a 后面跟 0~n 个 b，即 a(b*)
r"(ab)*"  # (ab) 重复 0~n 次
r"ab+"    # a 后面跟 1~n 个 b
```

> 要重复“多个字符”，必须 **先分组**: `(abc)+` ，而不是 `abc+` (后者只重复 c)。

## 3.3、贪婪 (默认)

```python
re.search(r'"(.*)"', 'a="x" b="y"').group()   # '"x" b="y"'
```

> `.*` 先把整行吞掉，然后 **从后往前** 退回，直到能匹配上 `"` -- 所以停在最后一个引号。

## 3.4、懒惰：量词后加 `?`

```python
re.search(r'"(.*?)"', 'a="x" b="y"').group()  # '"x"'
```

> `.*?` 先尽量少吃，**从前往后** 扩展，所以停在第一个引号。

| 贪婪 | 懒惰 | 占有 (3.11+) |
|---|---|---|
| `*` | `*?` | `*+` |
| `+` | `+?` | `++` |
| `?` | `??` | `?+` |
| `{m,n}` | `{m,n}?` | `{m,n}+` |

## 3.5、回溯过程图解

以 `a*b` 匹配 `"aaac"` 为例：

```text
输入: a a a c
      ↑
① a* 贪婪，吞掉 aaa
   位置: a a a [c]   需要 b，遇到 c → 失败
② 回退 1 个
   位置: a a [a] c   需要 b，遇到 a → 失败
③ 回退 2 个
   位置: a [a] a c   需要 b，遇到 a → 失败
④ 回退 3 个
   位置: [a] a a c   需要 b，遇到 a → 失败
⑤ 从位置 0 开始都试过了 → 整体失败
```

这就是 **回溯**：**先贪心到底，失败再一步步退**。

## 3.6、占有量词与原子组 (3.11+)

吞掉之后 **绝不回退**，用来主动切断指数级回溯。

```python
re.match(r"a*a",   "aaa")   # 匹配（贪婪，回退 1 个）
re.match(r"a*+a",  "aaa")   # None  （占有，不回退）—— 实测
re.match(r"(?>a*)a","aaa")  # None  （原子组）—— 实测
```

> 这两个特性在写高性能正则时非常有用，但也会 **改变匹配语义**，用错会漏匹配。

## 本章要点

1. 量词只作用于前一个原子，重复多字符要分组
2. 默认贪婪，加 `?` 边懒惰，加 `+` 变占有(3.11+)
3. 提取“一对引号之间”优先级：`"[^"]*"` > `".*?"` > `".*"`
4. 回溯 = 贪心 + 逐级退回，是性能问题的根源。

# 第四章 位置：锚点与断言

## 4.1、锚点 (零宽，不消耗字符)

| 写法 | 含义 | 备注 |
|---|---|---|
| `^` | 字符串开头 | `re.M` 下也是每行行首 |
| `$` | 字符串结尾，**或结尾换行之前** | 所以 `"abc\n"` 能被 `abc$` 匹配 |
| `\A` | 字符串开头 (严格) | 不受 `re.M` 影响 | 
| `\Z` | 字符串结尾 (严格) | 不受 `re.M` 影响，不认尾部换行 |
| `\b` | 单词边界 | `\w` 与 `\W` 的交界处 |
| `\B` | 非单词边界 | --- |

```python
re.findall(r"^\w+", "abc\ndef", re.M)      # ['abc', 'def']
re.findall(r"\bcat\b", "cat category")     # ['cat']
re.findall(r"\Bcat\B", "scatter")          # ['cat']
```

### `$` vs `\Z` 的差别

```python
bool(re.search(r"abc$", "abc\n"))   # True   ← $ 认结尾换行
bool(re.search(r"abc\Z", "abc\n"))  # False  ← \Z 只认绝对结尾
```

> **校验“整串”时用 `re.fullmatch` 最省心**，它天然排除了尾随换行等边界问题。

## 4.2、零宽断言 (环视)

“零宽” = 只检查条件，**不消耗字符**，所以可以连续叠加。

| 写法 | 名称 | 含义 |
|---|---|---|
| `(?=...)` | 先行肯定 | 后面 **必须** 是 ... |
| `(?!...)` | 先行否定 | 后面 **不能** 是 ... |
| `(?<=...)` | 后行肯定 | 前面 **必须** 是 ... |
| `(?<!...)` | 后行否定 | 前面 **不能** 是 ... |

```python
re.findall(r"\d+(?=\u5143)", "100\u5143 200\u5757")     # ['100']   后面是"元"
re.findall(r"(?<=\$)\d+", "$100 \u20ac200")            # ['100']   前面是 $
re.findall(r"\b\w+(?!\w)", "ab cd")                    # ['ab','cd']
```

### 断言的三个经典用法

#### 只取内容,不取边界

```python
re.search(r"(?<=user=)\w+", "id=7 user=alice").group()   # 'alice'
```

#### 密码强度：多个条件同时满足

```python
pwd = r"^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d@$!%*?&]{8,}$"
re.fullmatch(pwd, "Abc12345")   # 匹配（实测）
re.fullmatch(pwd, "abcdefgh")   # None
```

读法：`(?=.*[a-z])` = “从当前位置往后扫，某处必须有小写字母”，四个断言叠加 = 四个条件都满足。

#### 排除某些行

```python
re.findall(r"^(?!.*test).*$", text, re.M)   # 不含 test 的所有行
```

## 4.3、后行断言必须是“定长”

Python 的 `(?<=...)` 不允许变长，否则报错：

```python
re.compile(r"(?<=a+)b")
# re.error: look-behind requires fixed-width pattern
```

| 想匹配 | 写法 |
|---|---|
| `(?<=abc)` | 支持 定长 |
| `(?<=a{3})` | 支持 定长 |
| `(?<a\|ab)` | 不支持 不同长度分支 (3.11 前不行，现在部分支持？保守起见别用) |
| `(?<=a+)` | 不支持 变长 |

变长需求 -> 用 `regex` 模块，或改成捕获组。

## 4.4、`\b` 的实际语义

`\b` 是 `\w` 和 `\W` 之间的位置 (字符串首尾也算)

```python
re.findall(r"\b\d{3}\b", "abc 123 4567")   # ['123']
```

> 中英混排时要注意：汉字也属于 `\w` ，所以 `中a` 之间 **没有** `\b`。

## 本章要点

1. 锚点是零宽位置，不占字符
2. `$` 认尾部换行，`\Z` 不认；校验整串用 `fullmatch` 。
3. 断言不消耗字符，可叠加，是“多条件同时满足”的标准写法
4. 后行断言必须定长

# 第五章 分组、捕获与引用

## 5.1、捕获组 (...)

圆括号有两个作用：**分组** (改变量词作用范围) + **捕获** (把内容存起来)

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "2026-10-29")
m.group(0)      # '2026-10-29'  整体
m.group(1)      # '2026'
m.group(2)      # '10'
m.groups()      # ('2026', '10', '29')
m.span(1)       # (0, 4)        位置区间
```

## 5.2、非捕获组 `(?:...)`

只分组，不占编号，不保存内容。**性能更好，编号更清晰**。

```python
# 提取协议 + 域名，但不想把协议存下来
re.findall(r"(?:https?)://([\w.-]+)", "http://a.com https://b.com")
# ['a.com', 'b.com']
```

| 对比 | 捕获组 `(x)` | 非捕获 `(?:x)` |
| 占编号 | 支持 | 不支持 |
| 保存内容 | 支持 | 不支持 |
| 性能 | 略慢 | 略快 |
| 用途 | 要取值 | 只要结构 | 

## 5.3、命名分组 `(?P<name>...)`

可读性最好的写法，强烈推荐用于复杂正则。

```python
m = re.search(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})", "2026-10-29")
m.groupdict()          # {'y': '2026', 'm': '10', 'd': '29'}
m.group("y")           # '2026'
```

> 语法是 **Python 特有** 的 `(?P<name>...)`，PCRE 用 `(?<name>...)`。迁移时要注意。

## 5.4、反向引用

**匹配模式里** 引用之前捕获的内容：

```python
re.search(r"(\w)\1", "aab").group()          # 'aa'      连续重复字符
re.search(r"\b(\w+)\s+\1\b", "the the cat")  # 匹配 "the the"（重复单词）
re.search(r"(?P<c>\w)(?P=c)", "aab")         # 命名引用，等价
```

**替换字符串里**引用：

```python
re.sub(r"(\w+)@(\w+)", r"\2@\1", "a@b")        # 'b@a'
re.sub(r"(?P<x>\d+)", r"[\g<x>]", "12")        # '[12]'   命名用 \g<name>
re.sub(r"(\d+)", r"<\g<1>>", "12")             # '<12>'   用 \g<1> 更安全
```

> 替换串里 `\1` 会和 `\10` 混淆 (第 10 组 vs 第 1 组 +0)，**统一用** `\g<1>` 最稳。

## 5.5、条件模式 `(?(id)yes|no)`

“如果第 id 组匹配到了，就走 yes，否则就走 no”。(实测 Python 支持)

```python
re.fullmatch(r"(a)?(?(1)b|c)", "ab")   # 匹配（组 1 有值 → 要 b）
re.fullmatch(r"(a)?(?(1)b|c)", "c")    # 匹配（组 1 没值 → 要 c）
```

> 实际用途：区号可有可无的电话、可选前缀的 ID。

## 5.6、分组编号规则 (重要)

**从左到右，按左括号出现顺序编号** (从 1 开始，0 是整体)。

```python
r"((a)(b))(c)"
#  1 2 3  4
```

```python
m = re.match(r"((a)(b))(c)", "abc")
m.groups()     # ('ab', 'a', 'b', 'c')
```

> 嵌套分组会让编号变得难维护 -- 这就是 **命名分组** 存在的理由。

### `findall` 的分组陷阱 (最常踩)

```python
re.findall(r"\d+", "a1b22")           # ['1', '22']              无分组 → 整体
re.findall(r"(\d)\d", "a12b34")       # ['1', '3']               1 组 → 只返回组内容
re.findall(r"(\d)(\d)", "a12b34")     # [('1','2'), ('3','4')]   2 组 → 元组
re.findall(r"(\d)(?:\d)", "a12b34")   # ['1', '3']               非捕获组不算
```

#### 要“整体 + 分组” -> 用 `finditer`:

```python
[m.group(0) for m in re.finditer(r"(\d)\d", "a12b34")]   # ['12', '34']
```

## 本章要点

1. `()` 同时管分组和捕获；只要结构就用 `(?:)`
2. 复杂正则一律用命名分组 `(?P<n>)`
3. `\1` 在模式里是反向引用，在替换串里是 “插入组内容”。
4. `findall` 有捕获组时返回组内容而非整体 -- 这是 Python 特有的坑。

# 第六章 分支与优先级

## 6.1、分支 `|`

```python
re.fullmatch(r"cat|dog", "dog")        # 匹配
re.findall(r"cat|dog", "cat dog cow")  # ['cat', 'dog']
```

### 分支是 “或”，不是 “且”，且按 **从左到右** 尝试，第一个成功的就返回 (回溯引擎)。

```python
re.match(r"a|ab", "ab").group()   # 'a'，不是 'ab'
```

> 所以 **把更长的分支写前面**：`ab|a`。

## 6.2、优先级表

| 优先级 | 元素 | 例子 |
|---|---|---|
| 1 (最高) | 分组 `(...)` | 强制改变结合顺序 |
| 2 | 量词 `* + ? {m,n}` | `ab*` = `a(b)*` |
| 3 | 原子：字符、`.`、`[..]`、`\d`、锚点 | --- |
| 4 | 连接 (并列) | `abc` |
| 5 (最低) | 分支 `\|` | `ab\|cd` = `(ab)\|(cd)` |

```python
r"ab|cd"    # 匹配 "ab" 或 "cd"
r"a(b|c)d"  # 匹配 "abd" 或 "acd"
r"abc*"     # a + b + (c 重复)
r"(abc)*"   # abc 整体重复
```

## 6.3、字符类 vs 分支：优先用字符类

| 写法 | 性能 | 可读性 |
|---|---|---| 
| `[aeiou]` | 好 一次判断 | 好 |
| `a|e|i|o|u` | 不好 5 次尝试 | 一般 |
| `gr[ae]y` | 好 | 好 |
| `gray|grey` | 不好 | 好 |

```python
# 推荐
r"gr[ae]y"
# 不推荐
r"gray|grey"
```

## 本章要点

1. `|` 优先级最低，多字符分支要加括号
2. 回溯引擎“先到先得”，长分支写在前面
3. 能用字符类就不用分支，快且短

# 第七章 引擎原理与性能(ReDos)

## 7.1、回溯引擎怎么工作

```text
对字符串的每个起始位置:
    调用 match(pattern, pos)
        ├─ 遇到量词 → 贪心吃到头，记下"回退点"
        ├─ 后续失败 → 回到最近的回退点，退一步，再试
        └─ 所有回退点耗尽 → 失败，换下一个起始位置
```

关键：**回退点是栈式的**。嵌套量词会让回退点组合爆炸。

## 7.2、灾难性回溯 (实测)

```python
re.match(r"(a+)+b", "a" * n + "c")     # 结尾是 c，注定失败
```

| n | 耗时|
|---|---|
| 16 | 0.002s |
| 20 | 0.033s |
| 24 | 0.601s |

每 +4 个字符约 x16 (指数级，$2^{(n - 1)}$ 种分组方案)。

对照：

| 正则 | n=24耗时 | 相对 |
|---|---|---|
| `(a+)+b` | 0.601s | 1x |
| `a+b` | 0.0001s | **约 5000 倍快** |

### 为什么指数爆炸

`(a+)+`对 n 个 a 的所有可能“切分方程”都要试一遍：

```python
aaaa = (aaaa) = (aaa)(a) = (aa)(aa) = (aa)(a)(a) = (a)(aaa) = ...
```

切分方案数是 $2^{(n-1)}$。引擎并不知道这些切分“等价”，只能逐个试。

## 7.3、ReDoS (正则拒绝服务)

**攻击模型**：程序里有一个“嵌套量词 + 用户可控输入”，攻击者构造长字符串让匹配耗时指数增长，占满 CPU。

```python
# 危险代码
re.fullmatch(r"^(\w+\s?)*$", user_input)     # 输入 "aaaa...!" 即可打满 CPU
```

### 自查清单

| 信号 | 说明 |
|---|---|
| `(x+)+`、`(x*)*`、`(.*)*` | 头号杀手 |
| 量词套量词 | 任何 `(... + ...)+` 形态 |
| 多个 `.*` 串联 | `.*a.*b.*` 组合爆炸 |
| 无锚点的长模式 | 每个位置都要试 |
| 用户输入直接拼进正则 | 可能被注入 `(?=)` 等 |

## 7.4、优化清单 

| 手段 | 示例 |
|---|---|
| **扁平化嵌套量词** | `(a+)+b` -> `a+b` |
| **用否定字符类代替 `.*` | `".*?"` -> `"[^"]*"` |
| **加锚点** | `^` `\b` 让引擎快速失败 |
| **具体化** | `.*-.*` -> `\d{4}-\d{2}` |
| **字符类代替分支** | `a\|b\|c` -> `[abc]` |
| **非捕获组** | `(?:...)` 省状态 |
| **原子组 / 占有量词** | `(?>a+)`、`a++` (3.11+) |
| **限制重复上限** | `\w{1, 50}` 而非 `\w+` |
| **先做廉价预筛** | `if "ERROR" in line:` 在上正则 |
| **预编译** | 循环外 `re.compile()` |

## 7.5、DFA 引擎的取舍

如果你需要 “绝对不能指数爆炸” 的场景 (网关、WAF、用户输入)，可以考虑线性引擎：

| 场景 | 方案 | 
|---|---|
| Python 内部 | 用 `re`，但严格审计正则 |
| 需要线性保证 | `google-re2` (Python 绑定) |
| 需要递归 / 变长后行 | `regex` 模块 (仍是回溯) |
| 高并发网关 | 换成 Go/Rust 的正则库 |

## 本章要点

1. 回溯 = 贪心 + 退栈，嵌套量词是指数炸弹
2. `(a+)+b` 24 字符就要 0.6秒，30字符基本卡死
3. 防御核心：**别写嵌套量词、加锚点、用否定字符类、限制重复上限**
4. 用户可控输入 + 复杂正则 = 安全漏洞

# 第八章 Python `re` 模块

## 8.1、七个核心函数

| 函数 | 作用 | 返回 | 起始位置 |
|---|---|---|---|
| `re.search(p, s)` | 找到第一个匹配 | `Match` / `None` | 任意 |
| `re.match(p, s)` | 从开头匹配 | `Match` / `None` | 必须 0 |
| `re.fullmatch(p, s)` | 整串匹配 | `Match` / `None` | 必须 0 且到结尾 |
| `re.findall(p, s)` | 所有匹配 | `list` | 任意 |
| `re.finditer(p, s)` | 所有匹配(惰性) | 迭代器 | 任意 |
| `re.sub(p, r, s, count=0)` | 替换 | `str`| 任意 |
| `re.subn(p, r, s)` | 替换并计数 | `(str, n)` | 任意 |
| `re.split(p, s)` | 分割 | `list` | 任意 |

```python
re.search(r"b", "abc")       # 匹配到 b
re.match(r"b", "abc")        # None（不在开头）
re.fullmatch(r"\d+", "123a") # None（不是整串）
re.subn(r"a", "b", "aaa")    # ('bbb', 3)
```

### `match` vs `fullmatch` vs `search` (必分清)

```python
s = "abc13800138000xyz"
re.search(r"\d{11}", s)      # 匹配 → 误判为合法手机号
re.match(r"\d{11}", s)       # None  → 但 "13800138000xyz" 会误过
re.fullmatch(r"\d{11}", s)   # None  → 唯一正确
```

> 校验场景永远用 `fullmatch`。

## 8.2、`Match` 对象

```python
m = re.search(r"(?P<y>\d{4})-(\d{2})", "date: 2026-10")
```

| 成员 | 结果 | 说明 |
|---|---|---|
| `m.group(0)` / `m.group()` | `'2026-10'` | 整体 |
| `m.group(1)` / `m.group("y")` | `'2026'` | 按编号或名字 |
| `m.groups()` | `('2026', '10')` | 所有组 |
| `m.groups("X")` | 未参与匹配的组填 `"X"` | `default` 参数 |
| `m.groupdict()` | `{'y':'2026"}` | 命名组字典 |
| `m.start()` / `m.end()` / `m.span()` | `0 / 7 / (0, 7)` | 位置 | 
| `m.expand(r"\2/\1")` | `'10/2026'` | 用模板展开 |
| `m.re` / `m.string` | 原 Pattern / 原串 | --- |

## 8.3、编译与缓存

```python
PAT = re.compile(r"\d{4}-\d{2}-\d{2}", re.ASCII)   # 预编译，可复用
PAT.findall(text)
PAT.pattern      # 原始模式字符串
PAT.flags        # 标志位
PAT.groups       # 组数
PAT.groupindex   # {'y': 1} 命名组映射
```

**内存缓存**：`re` 会缓存最近 512 个已编译模式 (`re._MAXCACHE == 512`，实测)，所以小脚本不 `compile` 也不慢。但 **循环里反复调用** 仍然建议预编译。

> `re.Pattern` 对象不可变、**线程安全**，可以全局共享。

## 8.4、标志位

| 标志位 | 简写 | 作用 |
|---|---|---|
| `re.IGNORECASE` | `re.I` | 忽略大小写 |
| `re.MULTILINE` | `re.M` | `^` `$` 匹配每行 |
| `re.DOTALL` | `re.S` | `.` 匹配换行 | 
| `re.VERBOSE` | `re.X` | 忽略空白与 `#` 注释 |
| `re.ASCII` | `re.A` | `\w \d \s \b` 只认 ASCII |
| `re.DEBUG` | --- | 打印编译后的指令 |

组合用 `|` ：

```python
re.compile(r"^error", re.I | re.M)
```

### 内联标志

```python
r"(?i)abc"        # 全局，3.11+ 只能放在模式最开头
r"(?i:abc)"       # 局部作用域，只影响这一组
```

```python
re.compile(r"a(?i)b")
# re.error: global flags not at the start of the expression at position 1
```

## 8.5、替换进阶

```python
# ① 反向引用
re.sub(r"(\w+)@(\w+)", r"\2@\1", "a@b")          # 'b@a'
# ② 命名引用
re.sub(r"(?P<x>\d+)", r"[\g<x>]", "12")          # '[12]'
# ③ 函数式替换
re.sub(r"\d+", lambda m: str(int(m.group()) * 2), "a1b22")   # 'a2b44'
# ④ 限制次数
re.sub(r"a", "b", "aaa", count=1)                # 'baa'
# ⑤ 计数
re.subn(r"a", "b", "aaa")                        # ('bbb', 3)
```

> 用 `\g<0>` 表示 “整体”，因为它能避免 `\1` 与数字的歧义

## 8.6、`VERBOSE` 写法：复杂正则的标配

```python
LOG = re.compile(r"""
    (?P<date>\d{4}-\d{2}-\d{2})   \s+     # 日期
    (?P<time>\d{2}:\d{2}:\d{2})   \s+     # 时间
    (?P<level>[A-Z]+)             \s+     # 级别
    user=(?P<user>\w+)                    # 用户名
    (?:\s+ip=(?P<ip>[\d.]+))?             # IP（可选）
""", re.VERBOSE)

line = '2026-10-29 11:23:56 ERROR user=alice'
m = LOG.match(line)
m.groupdict()
# {'date': '2026-10-29', 'time': '11:23:56', 'level': 'ERROR',
#  'user': 'alice', 'ip': None}
```

`re.VERBOSE` 规则：

- 空白被忽略 (要匹配空格就写 `\` 或 `[ ]`)
- `#` 到行尾是注释
- 字符类 `[ ]` 内的空格 **不被忽略**

## 8.7、调试

```python
re.compile(r"(?P<y>\d{4})-(\d{2})", re.DEBUG)
# 打印 sre 指令序列，能看到引擎如何理解模式
```

| 手段 | 用途 |
|---|---|
| `re.DEBUG` | 看编译后的指令 |
| `re.error` | 语法错误，带位置 |
| 分布测试 | 先 `\d+` ，在逐步加约束 |
| `regex101.com` | 可视化回溯 (选 Python 方言) |

## 8.8、版本差异

| 特性 | 版本 |
|---|---|
| `re.fullmatch()` | 3.4 |
| 空匹配在 `sub / spilt` 中的改进 | 3.7 |
| 局部内联标志 `(?i...)` | 3.6 |
| **原子组 `(?>...)`、占有量词 `*+`** | **3.11** |
| 全局内联标志必须放开头 | 3.11 (之前只是警告) |
| `re` 缓存 512 个 | 长期稳定 |

## 本章要点

1. 校验用 `fullmatch`，提取用 `search / findall`
2. `Match` 有 `group / groups / groupdict / span`，够用了
3. 复杂正则必用 `re.VERBOSE` + 命名分组
4. `Pattern` 线程安全，可全局复用
